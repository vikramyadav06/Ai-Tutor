# Decisions

Choices not fixed by TECH_SPEC.md, with the reason. Newest last.

| Date | Decision | Reason |
| --- | --- | --- |
| 2026-11-03 | Module folders live directly under the subject (`core/subjects/<subject>/<module>/`) and `catalog.json` no longer has a `folder` field; the path is derived. | Matches TECH_SPEC §2 (`<subject-id>/<module-id>/lesson.json`) and keeps subjects movable. |
| 2026-11-03 | `start.py`'s hard-coded plan rules became data in each subject's `catalog.json`: `questions` (subject onboarding questions) and `rules` (`when` → `add_modules` / `add_focus` / `shorten`), plus `schedule_last`. Format: `core/teaching/subject-catalog.md`. | TECH_SPEC §2 says its plan rules become subject data. Plans are unchanged: a test checks all 135 Playwright answer combinations against the old `start.py` output. |
| 2026-11-03 | `tools/learner.py` is created in Phase 1 with `onboard`, `plan`, `progress`, `model`, `notes`, `add-term`, `show`. Phase 2 adds the identity, learner code and `sharing` commands TECH_SPEC §4/§9 describe. | Phase 1 needs a deterministic, testable way to write profiles and plans (§14), and the spec already assigns learner state to this tool. |
| 2026-11-03 | Learner files: `learner/profile.json` (name optional, `age_band`, `mode`, `level`, `explain_language`, `hours_per_day`, `sharing: false`, subjects), `learner/model.json` (the §5.1 `learner_model` fields), `learner/subjects/<id>/{answers.json, plan.json, plan.md, notes.md, progress.md}`, `learner/sessions/<uuid>.jsonl`, `learner/private_terms.json` as `{"terms": [...]}`. | One place per concern; `model.json` mirrors the Phase 2 record so `collect.py` can copy it after scrubbing. |
| 2026-11-03 | Enums not in the spec: `journey_stage` = `new, beginner, intermediate, advanced, revising`; `pace` = `slow, steady, fast`; `preferred_styles` = `hands-on, step-by-step, examples, analogies, visual, theory-first, practice-questions, discussion`. The same style list is used for a teaching move's `style`. | §5.1 names these fields without values. Phase 2 schemas should reuse these lists. |
| 2026-11-03 | Session log step `type` also allows `quiz` (revision quizzes) and `free` (a question the tutor improvised), besides the six lesson step types. Events carry UTC times at minute precision. | Revision quizzes and improvised checks are part of teaching and worth logging; minute precision matches §5.1 `started_at`. |
| 2026-11-03 | `log_session.py summary` reports patterns over the last N sessions (struggled modules, hints, slow steps, signals, moves/styles that work or don't). `core/teaching/adaptation.md` maps each pattern to a teaching change. | Gives the "adapt after a few sessions" goal a concrete, testable mechanism. |
| 2026-11-03 | The onboarding name is optional and stored only locally; the full name and each part are added to `private_terms.json` automatically. | People often go by one part of their name; the scrubber (Phase 2) needs every form. |
| 2026-11-03 | `tools/validate.py` treats flagged text (injection phrases, unknown link hosts, private terms) as a failure (exit 1), listed separately from format errors. It also checks practice paths stay inside the repo. | A flagged lesson must not be taught or merged until a person has looked at it (§12). |
| 2026-11-03 | `core/allowed_hosts.txt` starts with the practice sites and official docs the Playwright lessons use, plus a few open educational sites (Wikipedia, Khan Academy, NCERT, OpenStax). `github.com` is **not** listed (anyone can host anything there); `docs.github.com` is. | Smallest list that keeps current lessons valid and lets new subjects cite standard references. |
| 2026-11-03 | Root `pytest.ini` runs `tests/` only and no longer adds `--tracing retain-on-failure` by default. | That option needs pytest-playwright, which tutor tests must not require. Playwright learners can pass it themselves. |
| 2026-11-03 | `requirements.txt` moved to `core/subjects/playwright-python/requirements.txt`. Added `requirements-tutor.txt` (the §1 pins) and `requirements-dev.txt` (adds `pytest==8.3.3`). | §1: subject packages stay with the subject. Tests need pytest, which §1 does not list. |
| 2026-11-03 | `tools/content/setup_basics.py` (the one-off generator of the first two lessons) moved to `archive/content-scripts/`. `CURRICULUM.md` moved into the Playwright subject. | Neither is used by the tutor; both stay for reference. |
| 2026-11-03 | `AGENTS.md` starts with a short "building the platform instead?" rule: if the person is the owner or a developer, act as a developer and follow TECH_SPEC.md instead of onboarding. | CLAUDE.md now only points to AGENTS.md, so later build phases still need a way in. |
| 2026-11-03 | Generated lessons are written in the learner's `explain_language`. | Lessons declare `explain_language` (§13), so the core can hold several languages; reviewers can translate later. |
| 2026-11-03 | Owner requirement: the learner only ever experiences a tutor. Recorded as TECH_SPEC §15 so it binds every later phase; PLAN.md's "Session saved." line now says the learner sees nothing. | Asked by the owner before approving Phase 1. |
| 2026-11-03 | One entry point for background work, `tools/tutor.py`: `record` (one JSON payload per batch covering steps, moves, signals, exercises, private terms, notes, module done, model, progress entry, feedback, end), `context`, and `hook session-start|session-end`. Agents no longer call `log_session.py` or `learner.py model/notes/add-term` directly. | Keeps bookkeeping to one tool call per batch for every agent, with or without hooks. |
| 2026-11-03 | Hooks: SessionStart (`startup|resume|clear|compact`, 30 s) prints private context as `hookSpecificOutput.additionalContext`; on `startup`/`clear` it first finishes the previous session and retries the queue. SessionEnd (30 s) closes the log and commits. Commands try `python3` then `python`, with stderr discarded. | From the current hooks docs: SessionStart stdout goes to Claude's context; SessionEnd can't block, has a 1.5 s default budget raised by a per-hook `timeout` up to 60 s, and doesn't run when a terminal is just closed. |
| 2026-11-03 | Session-end commits run `git add` + `git commit -- my-work core/subjects` on the current branch, message `tutor: save work and lessons`, with a neutral `tutor <tutor@invalid>` identity only if the learner has none. Never pushes. Nothing happens without `learner/profile.json`. | Commits only the learner's work and generated lessons, never anything they staged elsewhere, and never a developer's work in progress. |
| 2026-11-03 | Failure handling: bad input (unknown values, malformed items) is logged to `learner/tutor.log` and skipped, never retried. Other failures (disk, permissions, git) are queued in `learner/pending.jsonl` and retried at the next session start, up to 3 attempts. Exit code is always 0, except `learner.py onboard|plan`, which also report bad answers on stderr with exit 2 so the agent can correct them before teaching starts. | Retrying bad input can't help; the agent needs to know when onboarding answers are wrong, and the learner never sees stderr. |
| 2026-11-03 | `log_session.py start` no longer prints the session id (it is in `learner/sessions/current`); `validate.py` prints nothing on success. | "Tools print nothing on success." |
| 2026-11-03 | Permissions: allow exactly the four tutor scripts (python and python3 forms) and `Edit(/core/subjects/**)`. Deny `curl`, `wget`, `Read`/`Edit` of `.tutor/`, `Edit` of `learner/`. No git rules (git runs inside the tools and hooks). `rm` and `git push` are not denied, so a learner who explicitly asks can still approve them at a prompt. `.claude/settings.local.json` is git-ignored. | Narrowest list that avoids every bookkeeping prompt. Writing lessons is the one file edit the tutor makes on its own, so it needs an allow rule too. Running a learner's practice tests (`pytest my-work/...`) still prompts, because it runs their code. |
| 2026-11-03 | Repo names: Repo A `vikramwebgarh/Ai-Tutor`, Repo B `vikramwebgarh/Ai-Tutor-Platform`. | Given by the owner. |
